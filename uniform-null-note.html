The Uniform Null of the KS Branch

Which uniform the Kolmogorov–Smirnov branch tests against is settled, and deliberately. What is not settled is the p-value attached to it: the one ks.test returns is not the p-value of the test we are performing, and it costs us power.

Package version 0.99.22 Prepared during Bioconductor review 26 August 2026

What we are asking

The rank of a row inside one column is an integer in 1 … N, where N is the number of rows. Under the null hypothesis — the row has no friends — those ranks are independent and uniform on the integers 1, …, N. To hand that null to stats::ks.test we must name a continuous distribution, and therefore an interval.

We fit that interval to the row itself: its own smallest and largest rank. That is the right null for what the method looks for, and the reasoning is in the next section. But fitting two parameters to the sample you are testing invalidates the distribution ks.test inverts to get its p-value. The test is honest; the number attached to it is not.

The question, in one line

Should we compute Monte-Carlo critical values for the fitted-endpoint statistic, the way Lilliefors (1967) did for normality with unknown mean and variance? Or accept the conservativeness and document it?

Why the support is fitted to the row

The method looks for a structural break, not for a shift. A row whose ranks are spread evenly over some part of the scale — the bottom half, say — has no subset of columns standing out from the rest. It should be reported as having no friends, even though its ranks are plainly not uniform on 1 … N.

Fitting both endpoints to the row makes the test invariant to where the profile sits and how wide it is, which is exactly that requirement. A fixed support answers a different question. Measured over 2 000 rows at N = 1000 with eight columns, the fraction called non-uniform at 0.05:

A fixed support would flag every concentrated flat profile as a marker. That is not a bug in it — it is a different null, and a defensible one for a different question. It is not ours.

Where the endpoints come from

Three conventions are now implemented, selected by the uniform.null argument. A fourth existed and has been withdrawn.

The withdrawn mode was a defect

The old argument was called uniform.max and named only the upper endpoint. Its "c" setting fixed that endpoint at N while the lower one continued to come from the data, one line earlier and without being documented anywhere. Mixing a fitted lower end with a fixed upper one has no interpretation as a null hypothesis: the data touch the left edge of the declared support by construction and, with high probability, fall short of the right edge, so the KS statistic is inflated in a systematic direction.

It is the setting a user reaching for “the statistically careful option” would plausibly have chosen, and it is the one that produced false friends. It is removed rather than renamed.

At three columns the default never once produced a p-value below 0.05 in five thousand null rows. Two of the three points are pinned to the boundary; one is free; the statistic cannot get large enough. At five to ten columns it rejects around 0.035 instead of 0.05, so roughly a third of the intended sensitivity is gone. By twenty columns the loss is small.

This is not an argument against the convention. It is the Lilliefors situation exactly: the null is legitimate, the critical values are not. He answered it for normality with unknown mean and variance by tabulating the statistic under simulation, and the same is open to us.

A caveat we should not paper over

The gap between 650 and 7 399 is not all lost sensitivity. The fixed-support conventions count concentration as evidence, and gene loadings are concentrated: they are non-negative and normalised across patterns, which induces dependence between a gene’s ranks and departs from the i.i.d.-uniform null in its own right. A larger marker count is not by itself a better method.

A limitation worth recording either way

With few columns the KS branch has little power against the alternative the method is named for. At eight columns, friends placed in the top 1% of ranks, fixed support so that the size is right:

A single friend out of eight moves the KS statistic by at most 1/8, far short of what rejection needs at that sample size; the test needs roughly half the columns to be friends before it fires reliably. This is inherent to a KS test on k points and no choice of endpoints changes it. It does explain why the Bayesian branch, which fits the step model directly, is the more sensitive instrument for wide matrices with few columns.

What is already in the package

  • uniform.null replaces uniform.max, which named one endpoint and said nothing about the other — which is how the asymmetry survived unnoticed. The new argument names the whole convention.
  • "observed" is the default, so nothing in any existing analysis moves.
  • The "c" setting is gone.
  • unif_ks_test() used to compute its test twice, once on ranks mapped to the unit interval and once on the raw scale, discarding the first. The two are the same test — the KS statistic is invariant under a monotone transform applied to both sample and null — so the duplicate is deleted. It also jittered a second time while keeping the first jitter’s maximum as the upper endpoint, which could put a point outside the declared support.
  • The documentation now states both endpoints, and what each convention is for.

The question, restated

For Alexandra and Alexey

The convention is not in question: the support is fitted to the row because the method tests for a break, not for a shift.

What is in question is the p-value. ks.test gives us the one for a completely specified null, and ours has two parameters estimated from the sample being tested. Do we want Monte-Carlo critical values for the fitted-endpoint statistic — simulated once per k, or per k and N — so that the reported p-value is the p-value of the test we are running? Or is the conservativeness acceptable, to be stated in the documentation and left alone?

If the answer is to simulate: is there a closed form or a published tabulation for the uniform case with both endpoints estimated, or is this a Lilliefors-style table we would have to make ourselves?

Reproducing the tables

Every number above comes from this, against package version 0.99.22.

library(friends.test)

## size under the null, and the shift-invariance table
set.seed(20260822)
N <- 1000; R <- 5000
size <- function(k, gen, ...)
  mean(replicate(R, unif_ks_test(gen(k), ...)) < 0.05)

for (k in c(3, 5, 8, 20)) print(c(
  observed   = size(k, \(k) sample.int(N, k, replace = TRUE)),
  continuity = size(k, \(k) sample.int(N, k, replace = TRUE),
                    "continuity", max.possible.rank = N),
  randomized = size(k, \(k) sample.int(N, k, replace = TRUE),
                    "randomized", max.possible.rank = N)))

## flat but shifted: the reason the support is fitted
for (top in c(N, N %/% 2, N %/% 10)) print(c(
  fitted = size(8, \(k) sample.int(top, k, replace = TRUE)),
  fixed  = size(8, \(k) sample.int(top, k, replace = TRUE),
                "continuity", max.possible.rank = N)))

## the CoGAPS example
data(friends.test.cogaps.example)
fl <- friends.test.cogaps.example$loadings
for (m in c("observed", "continuity", "randomized")) {
  set.seed(7)
  cat(m, length(friends_test_ks(fl, uniform.null = m)), "\n")
}
