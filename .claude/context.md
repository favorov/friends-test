## Архитектура пакета

- **Строки** матрицы A — кандидаты в маркеры (гены, элементы).
- **Столбцы** — кандидаты в «друзья» (паттерны, клеточные типы, коллекции).
- Общий первый шаг: `row.int.ranks()` ранжирует каждый столбец независимо
  через `data.table::frankv(..., ties.method = "random")`.
- Два основных workflow: KS-тест (`friends.test`) и байесовский BIC
  (`friends.test.bic`).
- Оба возвращают одинаковый формат: вложенный именованный список,
  листья — `c(marker, friend, rank)`.
- Параллельность через `BiocParallel`, opt-in через параметр `BPPARAM`,
  по умолчанию `SerialParam()`.

## Ключевые технические решения

### SnowParam и .libPaths() (май 2026)

**Проблема**: `R CMD build` устанавливает пакет во временную директорию,
добавляет её в `.libPaths()` родительского процесса, но SnowParam-воркеры
запускаются как свежие `Rscript`-процессы и эту директорию не наследуют.
Результат: `Error in loadNamespace(x): there is no package called 'friends.test'`
при сборке виньетки на Windows CI.

**Решение** (два компонента, оба необходимы):
1. `local(..., envir = globalenv())` — замыкание несёт `globalenv()` как среду,
   не пространство имён пакета → десериализация на воркере не требует загрузки
   пакета.
2. `libs = .libPaths()` передаётся через `MoreArgs`, воркер вызывает
   `.libPaths(libs)` перед любым `friends.test::` вызовом → воркер может найти
   пакет.

Реализовано в `R/friends.test.r`, `R/friends.test.bic.r`.

### Иерархия классов BiocParallel (май 2026)

`MulticoreParam` **наследует от `SnowParam`**, то есть
`is(MulticoreParam(), "SnowParam")` == TRUE.
При проверке точного типа backend всегда использовать
`class(BPPARAM) == "SnowParam"`, а не `is(BPPARAM, "SnowParam")`.

### Тесты параллельности и dev-режим

`test_local()` / `pkgload::load_all()` загружает пакет только в память текущей
сессии, но не в `.libPaths()`. SnowParam-воркеры не могут его найти в dev-режиме.
Решение: `skip_if(pkgload::is_dev_package("friends.test"), ...)` в
SnowParam-тестах. MulticoreParam-тесты работают в dev-режиме (fork наследует
память родителя), но пропускаются на Windows: `skip_on_os("windows")`.

### Broken \link{} references

При удалении публичной функции из API нужно также убрать все `\link{ИМЯ}`
в roxygen-комментариях других файлов — иначе `R CMD check` даёт WARNING.

## Прогресс-бары: что решено и что тупик

**SerialParam — отполировано, слито в devel:**
1. `cli_progress_along()` с `clear = FALSE` — бар остаётся виден после завершения.
2. `format_done = "{cli::pb_name}{cli::pb_bar} {cli::pb_percent} | {cli::pb_elapsed}"`
   — вместо "ETA: 0s" при завершении показывается затраченное время.
3. Убран дублирующий `cli_progress_step("Identifying friends...")`
   в `friends.test.r`.

**Параллельные бэкенды (MulticoreParam, SnowParam):**
- `bpprogressbar = FALSE` принудительно (в `biocparallel-utils.r`).
- Показывается только текстовая метка шага через `cli_progress_step`.
- **Открытый вопрос**: красивый параллельный прогресс-бар так и не решён.

**Отвергнутые подходы** (не повторять):
- `progressr::with_progress` + `handler_cli()` с передачей `progressor`
  аргументом в воркеры — ветка `devel-fancy-progress`. Не отображается в
  VS Code R-терминале (не настоящий TTY) и даёт **5x замедление**:
  IPC-overhead от тысяч `p()` вызовов из форкнутых воркеров.
  Вывод: передача `progressor` в воркеры BiocParallel нежизнеспособна.
- per-worker `cli_progress_along` — нет TTY в суб-процессах.
- `bpprogressbar = TRUE` + ANSI cleanup — двойная строка, курсором не управлять.
- mcparallel + tempfile polling — слишком сложно.

## Скрипты синхронизации репозиториев (`utils/`)

```bash
./utils/sync_here_with_there.sh [--dry-run]   # ~/friends.test  -> R/friends.test
./utils/sync_there_with_here.sh [--dry-run]   # R/friends.test  -> ~/friends.test
```

Оба — тонкие обёртки над `utils/_sync_engine.sh`, который делает всю работу.

**Что делает.** Для каждого файла, отслеживаемого в обоих деревьях, берёт его
текущее содержимое в приёмнике и ищет самый свежий коммит в истории источника
с таким же содержимым — это стартовая точка. Все коммиты источника, тронувшие
файл после неё, воспроизводит в приёмнике с исходным сообщением, автором и
датой авторства. Совпадают последовательность, диффы и содержимое; id коммитов
закономерно другие.

**Почему это работает без общей истории.** Сравнение идёт по blob-хешам, они
контентные и потому сравнимы между несвязанными репозиториями. Общая история
не нужна — нужно только совпадение содержимого файла в одной точке. Это
существенно: до какого-то момента истории двух репозиториев разные (здесь
шли мелкими шагами, там коммиты были размером в версию).

**Гарантии.** Если хоть у одного файла стартовой точки нет — не делается
ничего вообще, ни по одному файлу. Требуется чистое рабочее дерево с обеих
сторон (неотслеженные файлы не мешают). Ничего не пушится. Берутся те ветки,
которые активны в момент запуска, — имена веток печатаются в шапке до любых
действий.

**Диагностика.** Всегда печатается шапка (репозитории, ветки, префиксы) и
счётчики `shared / already equal / to replay / diverged`. Дальше одно из:
план переноса и `done: N commit(s) written`; `already in sync`; либо список
файлов без стартовой точки с причиной — `target is ahead; run the opposite
script` (направление перепутано) или `both sides changed it independently`
(настоящий конфликт, руками).

**Коды возврата.** `0` — сделано или нечего делать; `1` — расхождение, ничего
не тронуто; `2` — не выполнены предусловия (грязное дерево, не git-репозиторий,
нет общих файлов — значит неверный префикс).

**Ограничение.** `git rev-list HEAD -- path` применяет стандартное упрощение
истории; на почти линейных историях это то, что нужно, но в сильно
merge-нагруженной ветке часть коммитов может быть свёрнута.

Проверено на клонах обоих репозиториев: содержимое всех 38 общих файлов
совпало побитово, диффы всех перенесённых коммитов совпали с оригинальными,
автор и дата сохранились, повторный запуск даёт `already in sync`, грязное
дерево и искусственное расхождение отрабатывают отказом.

### Решения по публичному API (21 августа 2026)

**Конвенция — snake_case.** Гайдлайн Bioconductor (раздел 16.2.6.1) предписывает
camelCase, Грусон в чек-листе разрешил и `_`. Выбран snake_case: внутренние
помощники (`.step_fit_compact`, `ft_bpparam`, `ft_bplapply_dbl` и прочие) уже
написаны так, и пакет становится однородным без правки внутренностей.

Имя пакета остаётся `friends.test` — точки в именах пакетов разрешены, Грусон
проверку имени прошёл.

**Экспорт — семь функций:**

```
friends.test                      -> friends_test
friends.test.bic                  -> friends_test_bic
row.int.ranks                     -> row_int_ranks
best.step.fit                     -> best_step_fit
best.step.fit.bic                 -> best_step_fit_bic
unif.ks.test                      -> unif_ks_test
step.fit.ln.likelihoods           -> step_fit_ln_likelihoods
step.fit.ln.likelihoods.fullmesh  -> прячем
```

`best_step_fit` и `best_step_fit_bic` **не сливаются** — параметры разные по
смыслу. Требование Грусона про дублирование закрывается вынесением общего ядра
во внутреннюю функцию при двух публичных обёртках.

**Слово «fullmesh» убирается из пакета целиком**, оно означало две
противоположные вещи:

```
.step_fit_fullmesh                -> .step_fit_enum      (полный перебор по l1)
step.fit.ln.likelihoods.fullmesh  -> .step_fit_profile   (возвращает профиль)
```

**Аргументы не переименовываются.** Запрет на точку касается только имён
экспортируемых функций — причина в диспетчеризации S3, к аргументам она
неприменима. Раздел 16.2.6.3 «Function arguments» про стиль имён молчит,
машинной проверки нет (среди ~60 проверок BiocCheck нет ни одной про имена), а
`simulate.p.value` и `rescale.p` — это имена аргументов из `stats::chisq.test`,
то есть совпадение с base R здесь достоинство. Это же и ответ ревьюеру, если
спросит.

**Имя данных `friends.test.cogaps.example` остаётся** — это объект данных, а не
функция, буква правила его не касается.

**Имена файлов приводятся в соответствие с именами функций** (`R/`, `man/`,

сессии, но принцип важнее: граница переноса не должна проходить внутри
`` `...` ``, `$...$` и `[...](...)`, иначе ломается inline-код и формулы
(первая версия скрипта превратила `$i$-th` в `$i$ -th`). Проверять двумя
способами: инвариантом по исходнику (разбить на блоки по пустым строкам,
схлопнуть пробелы, сравнить) и сборкой виньетки до и после — в виньетке есть
`set.seed(42)`, поэтому HTML воспроизводим и должен совпасть побайтово.

## Приоритет файлов с правилами

Правила лежат в трёх местах и частично дублируются. Приоритет (уточнён
5 августа 2026): `.claude/rules/comminication-rules.md` главный; `.copilot/rules.md`
и `copilot-rules.md` в корне действуют там, где не касаются явно Copilot.

Практически это значит: разделы про тесты и сборку, про синхронизацию
`~/friends.test` по явной команде и про структуру репозиториев есть только
в `.copilot/rules.md`, и они в силе. А трейлер
`Co-authored-by: Copilot <...>` оттуда не применяется — Claude подписывает
коммиты своим трейлером, выдавать себя за другой инструмент не нужно.
